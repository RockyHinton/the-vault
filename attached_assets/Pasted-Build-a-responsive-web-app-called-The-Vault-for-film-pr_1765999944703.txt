Build a responsive web app called “The Vault” for film production companies. The Vault is a secure, project-centric platform for storing, organizing, previewing, and tracking production and distribution documents across a film’s lifecycle. The primary goals are readability, visually clear layouts, fast navigation from film titles → broad categories → sub-categories, and a strong document experience (upload, download, preview on hover, metadata at a glance).

Tech stack and architecture

Use Next.js (App Router) + TypeScript.

UI: TailwindCSS with a clean, professional, high-contrast layout.

Components: use a modern component approach (cards, tables, tabs, breadcrumb).

Backend: use a simple API layer inside Next.js route handlers.

Database: use SQLite with Prisma (or Postgres if easier on Replit). Persist data.

File storage: store uploaded files locally in a /uploads directory for MVP, with DB records storing file path + metadata. Design so storage can be swapped later (S3).

Authentication: implement basic login for MVP (email + password) with sessions (NextAuth or a simple cookie-based session). Include roles.

Core user experience requirements

The app opens to a Projects dashboard listing film titles with search and filters.

Clicking a film opens a Project Workspace with a left sidebar for categories, a top breadcrumb, and a main content panel.

Navigation hierarchy must be clear:
Projects → Project → Category → Subcategory → Items (documents, tasks, records)

Every major page must be readable, uncluttered, and optimized for scanning.

Data model (MVP)
Create Prisma models (or equivalent) for:

User: id, name, email, passwordHash, role (Admin, Producer, TeamMember, External)

Project (Film): id, title, status (Development, Packaging, Financing, Production, Post, Distribution), logline, synopsis, genre, createdAt

Category: id, projectId, name (Script, Producing Partners, Financing, Action Points, Final Documentation, Distribution, Company Entities)

Subcategory: id, categoryId, name (e.g., under Script: Reader Analysis, Cast Wishlist, Script Versions; under Financing: Budget, Cashflow, Finance Plan, Schedule, Breakeven)

Document: id, projectId, categoryId, subcategoryId, title, type (PDF/DOCX/XLSX/IMG/OTHER), filePath, fileSize, uploadedByUserId, uploadedAt, versionNumber, status (Draft/Final/Signed), tags (string array), notes

DocumentMetadata: id, documentId, json (store extracted fields like: territory, counterparty, amount, dates, synopsis, score, etc.)

ShareLink: id, documentId, token, expiresAt, passwordHash(optional), watermarkText(optional), createdByUserId, createdAt, accessCount

Partner: id, projectId, type (CoProducer, SalesAgent, Bank, Investor), name, notes, pastProductions, fundingAccess, agreementStatus

FinanceRecord: id, projectId, kind (Budget, Cashflow, FinancePlan, Breakeven), versionLabel, notes, attachedDocumentId(optional)

Task: id, projectId, title, description, assignedToUserId, status (Open/Done), dueDate, createdAt, completedAt

ActivityLog: id, projectId, actorUserId, actionType, targetType, targetId, createdAt, detailsJson

Permissions and safety (MVP)

Role-based access:

Admin/Producer: full access

TeamMember: access assigned projects

External: access only share links (no internal browsing)

Basic security:

Validate uploads (file size limit, allowed types)

Sanitize filenames

Prevent directory traversal

Protect all project routes behind auth

Quality and usability requirements

Prioritize clarity: large readable typography, consistent spacing, clear headings.

Fast navigation: search within a project’s documents, filter by tag/type/status, sort by updated/uploaded.

Always show “where I am” via breadcrumb + highlighted sidebar.

Provide sensible empty states (“No documents uploaded yet” with upload CTA).

Keep styling cohesive and “premium professional” (film industry friendly; not playful).

Make it easy to extend into a real SaaS later (multi-tenant, S3 storage, real email service).
