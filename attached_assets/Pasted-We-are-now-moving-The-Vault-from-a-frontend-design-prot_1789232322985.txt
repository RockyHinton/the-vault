==================================================
PRODUCT CONTEXT
==================================================

The Vault is intended to become an extensive all-in-one operating system for film production companies.

It manages films across a lifecycle currently including:

Evaluation
→ Development
→ Production
→ Archive

The existing frontend has already been designed extensively and validated with our initial client, 3six9 Studios.

The frontend UX should therefore be PRESERVED as closely as possible when the backend is introduced.

The Vault is NOT intended to operate as one multi-tenant SaaS application containing multiple production companies.

DEPLOYMENT MODEL:

We are building ONE definitive master-template version of The Vault.

That master version will contain the complete product architecture, features and capabilities.

When The Vault is sold to a production company:

- the master application will be remixed/copied into a dedicated client instance
- that client will have its own deployment
- its own database
- its own file storage
- its own users
- its own projects
- its own secrets/environment configuration
- its own branding/configuration where applicable

Examples:

Master Vault
→ 3six9 Studios Vault deployment
→ Studio B Vault deployment
→ Studio C Vault deployment

These deployments are completely separate applications/data environments.

Therefore:

DO NOT design multi-tenancy.
DO NOT design tenant IDs on every database table.
DO NOT design cross-company user accounts.
DO NOT design organisation switching.
DO NOT introduce multi-tenant complexity that this deployment model does not require.

The goal is instead to make the master template exceptionally clean, reusable and configurable so new client deployments can be created safely and efficiently.

A lightweight Studio / Company Settings configuration is appropriate for things such as:

- studio name
- studio logo
- branding
- contact information
- configurable application settings

But this represents the ONE company using that deployment, not a tenancy system.
